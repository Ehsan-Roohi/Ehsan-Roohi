## Physical and numerical interpretation

This is the third numbered course assignment. It extends the compressible airfoil work with viscous fluxes, nodal reconstruction and a mixed mesh. The preserved viscous case has **838 nodes, 1374 cells: 232 quadrilaterals and 1142 triangles**. Its source declares Mach parameter 1.2, Reynolds parameter 1000 and zero angle of attack. Keep these settings distinct from other archived variants.

The inviscid part transports mass, momentum and energy across faces. `VISCOUS` and `CELLNODE` reconstruct local quantities and viscous/thermal flux contributions. Wall treatment, near-wall resolution and gradient consistency matter here; a residual history alone is insufficient evidence of a correct viscous solution.

## Defects found by the current checks

The two original sources fail GNU Fortran's loop-index rules because `VISCOUS` assigns the host variable `I` while the caller is inside a `DO I` loop. The compatibility working copy declares a local integer `I` in that subroutine, allowing compilation while preserving the original source file.

The main viscous case then fails a bounds check in `CELLNODE`: an uninitialized entry in `NODE_VICINITY` is used to index `RHOO`. The separate quantity variant lacks co-located node/connectivity inputs and encounters EOF during mesh input.

A further geometry defect is present in the main source: the quadrilateral `Y_CELL` formula ends with `XNODE(N4)` instead of `YNODE(N4)`. Evaluating that expression on the actual mesh affects all 232 quadrilaterals; the maximum absolute y-coordinate error is approximately **0.25237 in the mesh's coordinate units**. This changes the geometry used in gradients and cannot be accepted as a validated formulation.

The [mesh evidence](../../docs/validation/mesh-validation.json) and [execution report](../../docs/validation/README.md) record these findings. The input mesh itself passes basic connectivity/area checks; the solver's use of that mesh needs repair and further physical validation.
